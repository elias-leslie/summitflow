# Rust host collector prototype

`./build.sh` builds the pinned release binary; `./run.sh --mode baseline --samples 2 --interval-ms 100` builds only when the binary is missing or stale, then replaces the shell with the binary. `--mode detail` emits every successfully parsed process. Output is one compact JSON object per sample on stdout; build and read diagnostics use stderr. This is a finite measurement fixture, not a service.

The provider is `rust-sysinfo-proc`. `sysinfo 0.39.6` supplies total and available RAM and used swap. `/proc/stat` supplies aggregate CPU ticks; `/proc/pressure/{cpu,memory,io}` supplies PSI; `/proc/net/dev` supplies non-loopback network counters; `/proc/diskstats` supplies whole-device sector counters (512-byte sector units) for names enumerated in `/sys/block`, excluding `loop*` and `ram*` devices; `statvfs("/")` supplies root filesystem capacity and available bytes. `/proc/<pid>/stat` supplies PID, name, CPU time, start ticks, and resident pages; `/proc/<pid>/io` supplies byte counters. `sysconf` supplies clock ticks and page size. When requested, cgroup-v2 `cpu.stat` supplies `cpu_usage_usec` directly, `memory.current` supplies `memory_current_bytes`, and `io.stat` supplies `io_read_bytes` and `io_write_bytes` totals. Missing fields are JSON null with source/code errors.

CPU and I/O leaders require a prior sample with the same PID and start ticks. First-sample baseline contains only RSS leaders. Baseline scans all visible numeric `/proc` entries and emits the union of up to ten leaders per metric; detail emits every parsed row. Process I/O may be unavailable under permission restrictions while the remaining process fields are still emitted. `processes_permission_denied` counts denied stat or I/O reads; `processes_exited` counts stat reads that fail after directory enumeration. These are per-sample scan counts. The collector does not read boot ID; the downstream writer combines it with `start_ticks` for identity.

Limitations: `/proc` enumeration is not an atomic snapshot, and PID reuse during a scan is possible. Whole-device counters can include virtual/block-stack duplication and are host totals, not filesystem traffic. Root `statvfs` reports the current mount namespace. The runner's cached binary does not automatically rebuild for dependency changes unless the lockfile or manifest changes; run `./build.sh` after toolchain changes. No root privileges, outbound requests, journal reads, command lines, environment capture, or persistent output are used.
