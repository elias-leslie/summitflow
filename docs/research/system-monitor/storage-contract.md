# Local monitor store and query contract, version 1

Task `task-ea952b00a68b4940`. The Rust collector is the sole writer. The Python standard-library reader is shared by `st monitor` and the owner-only FastAPI adapter. Neither reader imports the collector or PostgreSQL. The internal SQLite file stays on a local filesystem under an owner-only state directory; the public JSON envelope is versioned independently of SQLite tables.

## State and identity

The service accepts `--state-dir` (managed default `~/.local/state/summitflow/monitor`) and `--project-identity` (the checked-in `project.identity.json`). `SUMMITFLOW_MONITOR_STATE_DIR` is an explicit standalone/test override; the managed unit, policy writer, and readers use the canonical home path even if `XDG_STATE_HOME` differs. The state directory and control socket are mode 0700/0600; DB files are mode 0600. It records host ID, Linux boot ID, collector version, and schema version. Each sample records UTC nanoseconds plus Linux monotonic nanoseconds; rates use the monotonic interval and never cross a boot-ID change. A process identity is `(boot_id,pid,start_ticks)`; `ppid` is a snapshot parent hint and must be resolved against the same snapshot because PIDs can be reused.

SQLite schema v1, created/migrated only by the collector before sampling:

- `meta(key TEXT PRIMARY KEY,value TEXT NOT NULL)` for schema, host and boot identity.
- `samples(id INTEGER PRIMARY KEY,sampled_at_ns INTEGER NOT NULL,monotonic_ns INTEGER NOT NULL,boot_id TEXT NOT NULL,mode TEXT NOT NULL,host_json TEXT NOT NULL,services_json TEXT NOT NULL,process_blob BLOB NOT NULL,processes_seen INTEGER NOT NULL,processes_permission_denied INTEGER NOT NULL,processes_exited INTEGER NOT NULL,errors_json TEXT NOT NULL,duration_ns INTEGER NOT NULL,capture_reason TEXT)` with an index on `(sampled_at_ns,id)`. `process_blob` is gzip-compressed compact JSON of the prototype-contract process rows. Baseline contains the union of per-metric leaders; detail contains all successfully visible processes. It never stores argv, environment or raw logs.
- `events(id INTEGER PRIMARY KEY,sampled_at_ns INTEGER NOT NULL,kind TEXT NOT NULL,severity TEXT NOT NULL,entity TEXT,details_json TEXT NOT NULL)` indexed on `(sampled_at_ns,id)`. Events include service-state changes, capture starts/stops, source failures, collector restart and retention gaps; details contain bounded structured fields, not raw journal text.
- `host_rollups(bucket_start_ns INTEGER PRIMARY KEY,sample_count INTEGER NOT NULL,values_json TEXT NOT NULL,coverage_json TEXT NOT NULL)` for one-minute host summaries. Each numeric bucket reports min/max/mean/last and number of valid readings, with explicit unavailable/gap counts. Raw samples are never silently interpolated.

Use WAL and `synchronous=FULL`; keep one writer and short read-only transactions. The collector owns checkpointing. A version mismatch is an explicit read error; a reader never alters/migrates state. Reader queries are bounded by time window, row count, returned bytes and cursor. Cursor binds filters, sort and last `(sampled_at_ns,id)`, and cannot inject SQL. Direct read of committed history must work while the collector and backend are stopped.

## Sampling, capture and retention

Baseline host/service observations every five seconds; lightweight process leader scan every 15 seconds. The same one-second loop scans all visible processes when a lease or trigger is active and persists detail at most every five seconds. Each detail tick first commits an independent baseline row with host/service values and leaders, then a detail row with host/service values and all visible processes at the same measurement time. Detail eviction leaves baseline rows intact; rollups count baseline rows once. Other one-second observations update in-memory state but are not directly queryable as process history. The collector loads core managed service names from `project.identity.json`, batches `systemctl --user show` state/cgroup discovery, reads cgroup-v2 counters where accessible, and labels main-PID fallback with the process scan's UTC and monotonic time. It records service state even when cgroup metrics are unavailable. The health probe is bounded to the configured loopback backend endpoint and must not block baseline collection.

An owner-local control socket accepts only `status`, `lease_start`, `lease_renew`, and `lease_end` with bounded JSON. Leases have opaque IDs and expire unless renewed; all leases share one detail loop. An observed managed-service transition into failed/unexpectedly stopped triggers detail immediately. Sustained high pressure uses the high thresholds owned by `backend/app/tasks/runtime_hygiene_common.py` (CPU 90%, memory 95%, disk 90% used or at most 10 GiB free), written to a stable runtime policy snapshot during managed installation. Three consecutive high observations enter detail and recovery hysteresis prevents flapping; missing trigger inputs are unavailable rather than healthy. No collector command performs state-changing service/process actions.

The managed build writes `state_dir/policy.json` atomically from those Python constants with `schema: 1`, `cpu_critical_pct`, `memory_critical_pct`, `disk_critical_pct`, `disk_critical_free_bytes`, and `source: "runtime_hygiene_common"`. The collector may override the path with `--policy-snapshot`. A missing or invalid snapshot leaves the pressure trigger unavailable and emits an error; baseline sampling and service-state triggers continue. The database basename is `monitor.sqlite3`, and `meta.schema_version` is `1`.

Target raw baseline coverage is 48 hours and one-minute rollups 14 days, subject to a 512 MiB total DB+WAL+SHM file budget and 1 GiB filesystem free headroom. Detail process blobs have a 192 MiB logical quota; raw baseline JSON and process blobs have a 256 MiB logical quota that does **not** count rollups. Rollups and all other SQLite pages still count toward the total file budget. Detail admission leaves 64 MiB of the total budget for WAL/other work. Pruning first deletes samples past the 48-hour age target, then evicts oldest detail under pressure, then may evict baseline older than **one hour**. Baseline from the last hour is protected from pressure eviction; if available space still cannot support a new write, the collector reports failure and leaves committed history readable. Incremental vacuum and checkpoint are attempted, but a long-lived reader can prevent WAL truncation, so a hard 512 MiB ceiling under that condition is not yet established. On cap, full disk, or SQLite failure, skip detail first and preserve prior commits. Expose current writer failure through the socket and staleness/service state through direct `st monitor status`, even if the failure itself cannot be persisted.

## Public query envelope

Observation and export responses use the common JSON envelope: `schema`, `generated_at`, `requested`, `coverage`, `items`, `next_cursor`, `truncated`, and `errors`. Each observation item has measured time, freshness, source/provider, mode, unit and availability where applicable. Successful `capture`, `capture-renew`, and `capture-end` are control acknowledgments instead: compact `ok` plus lease ID/expiry/detail state as applicable, without query items or schema version; failed commands return structured errors. Queries default to a 15-minute window, ten items and a 4 KiB valid-JSON output budget; `--limit` and `--max-bytes` remain capped. Series supports `--since`, `--until`, `--step`, entity and metric filters. Windows at most 24 hours use exact raw baseline samples; longer host history uses UTC-minute rollups and requires minute-aligned `since`, `until`, and step, rejecting ambiguous partial minutes. Disk/network byte-per-second rates require per-member raw counter continuity and therefore reject windows longer than 24 hours; rollups cannot reconstruct those rates. A raw series bucket provides `last_sampled_at` for exact drilldown. Process queries support `--at`, name/user/service filters and CPU/RSS/I/O sort; baseline results explicitly say `leaders_only`. `--at` chooses the newest sample at or before the requested time within twice its stated cadence, or returns an explicit gap. Logs are on-demand bounded journal cursor/time reads and are not stored in SQLite.

Availability codes include `ok`, `unsupported`, `permission_denied`, `timeout`, `error`, `stale`, `collector_stopped`, `not_collected`, `leaders_only`, and `retention_expired`. `null` plus an availability code means unavailable; zero is only an observed zero. Exports default to redacted. Remote endpoints require SummitFlow owner identity; the local socket and files are never exposed over a network listener.
