# Independent ST help acceptance

The baseline inventory is [`before.json`](before.json), captured through the installed `backend/.venv/bin/st` with a source-fingerprint check before and after. Its 665 help invocations cover 244 native Click nodes (including root and hidden aliases), 406 metadata pages across all 24 registered extension namespaces, and 15 manually selected `check`/`db` help routes. The inventory uses only Click/Typer command objects for structure and invokes actual `--help` paths for output. It does not dispatch mutating commands. Manual `check` tool passthroughs such as `check pytest --help` are deliberately excluded because they execute owner tools rather than ST help.

Acceptance after edits:

1. Every enumerated installed help route returns useful, nonempty output with a successful exit. New metadata routes are included if added. Every extension metadata route has its parent registered and resolves to the intended page; optional trailing newlines are normalized. No route is silently replaced by an unrelated sibling page.
2. Native command/group names, hidden aliases, option spellings, requiredness, defaults, types, flag status, multiplicity, and argument arity remain compatible. Extension binding names, owners, executables, and statuses remain stable. Any intentional route change must be called out separately.
3. Manual and passthrough help remains safe and accurate. `st check --help`, `st check --acceptance --help`, `st check codeql --help`, and `st db ... --help` must not execute checks, connect to a database, or mutate state. The existing `db` subcommand paths all returned the same root usage page in the baseline; any later specialization should improve routing without changing command behavior.
4. The installed entrypoint is used for verification, not only source-level formatting. Extension metadata help is rendered by ST without requiring owner execution. Held-out argument-routing probes must not turn an option value or an invalid prefix into an unrelated subcommand's help page; see [`help-route-probes-before.json`](help-route-probes-before.json). A positional ID equal to a sibling command after a selected command should remain on the selected command. `models --id list --help` must show root help because `list` is an option value; `models --id foo list --help` and `models --free list --help` must still show list help because the owner accepts options before the command.
5. Report help output cost as raw UTF-8 bytes and `ceil(bytes/4)` per invocation, with root/route distributions and representative navigation sequences. This is an output estimate, not measured model tokens or task success. Agent usefulness also requires an explicit command/flag path to the intended action; brevity alone is insufficient.

Baseline totals: 268 Click tree nodes, 24 extension namespaces, 406 extension metadata pages, 15 manual probes, 665 installed help captures, all exit 0 and nonempty. Aggregate output if an agent read every page is 268,042 bytes / 67,269 estimated tokens; this artificial whole-surface sum is only an inventory check, not a normal workflow cost. A normal agent reads a small route chain, which will be compared before and after.
