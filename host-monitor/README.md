# SummitFlow host monitor

`summitflow-host-monitor` is the resident, unprivileged Linux collector and the sole writer of `monitor.sqlite3`. Build with `cargo build --release` from this directory. The service launcher supplies `--project-identity`; `--state-dir` defaults to `$SUMMITFLOW_MONITOR_STATE_DIR` when set, otherwise `$HOME/.local/state/summitflow/monitor`. `--policy-snapshot` defaults to `state_dir/policy.json`. `--once` writes one baseline sample; `--samples N [--interval-ms M]` runs a finite loop for smoke checks.

The policy snapshot is JSON with `schema: 1`, `source: "runtime_hygiene_common"`, `cpu_critical_pct`, `memory_critical_pct`, `disk_critical_pct`, and `disk_critical_free_bytes`. A missing or invalid snapshot disables only pressure triggering and appears as `policy_error` in socket status.

The owner-only Unix socket is `state_dir/control.sock`. Send one JSON line, receive one JSON line. Commands are `{"command":"status"}`, `{"command":"lease_start","ttl_seconds":30}`, `{"command":"lease_renew","lease_id":"...","ttl_seconds":30}`, and `{"command":"lease_end","lease_id":"..."}`. TTL is clamped to 1–300 seconds; IDs are opaque 128-bit random hex strings. At most 16 leases may be active; `lease_start` then returns `{"ok":false,"error":"lease_capacity_reached","active_leases":16,"max_active_leases":16}`. Expired leases release slots before each command. Requests are capped at 4096 bytes and peer UID must match the collector owner. Status includes writer failure, policy error, latest observation, storage size, active and maximum lease counts, and bounded sample-plus-commit latency statistics.

The provider reads `/proc/stat`, `/proc/pressure/*`, `/proc/net/dev`, `/proc/diskstats` plus `/sys/block`, `/proc/<pid>/{stat,io,cgroup}`, and proc file metadata for numeric UID. Each observed process row includes a bounded Linux `state_code` and normalized `state` from proc stat; a process that exits during scanning is counted as exited coverage without a fabricated row. `samples.processes_permission_denied` counts only denied process stat reads. Denied process I/O reads keep the visible process row with null I/O counters and are counted separately as `host_json.process_io_permission_denied`; the host snapshot and socket latest value carry `process_scan_observed_at_ns` and `process_scan_observed_monotonic_ns` for freshness. A one-time `/etc/passwd` parse maps known UIDs to usernames without per-process NSS calls. `sysinfo` supplies host memory and swap. `statvfs` supplies root disk capacity. The batched `systemctl --user show` call supplies managed service state, cgroup path, and main PID; cgroup-v2 `cpu.stat`, `memory.current`, and `io.stat` supply whole-service metrics when readable. The main PID process snapshot is explicitly labeled as a fallback. The bounded loopback health probe runs on a background thread. No command lines, environment, or raw logs are stored.

SQLite uses WAL, `synchronous=FULL`, and 1 KiB pages for new databases, with schema v1 from the storage contract and gzip process JSON. The page size and three-sample rollup batch reduced measured writes on the SummitFlow btrfs host; existing databases retain their page size. Baseline rows with host, service, and process leader history are persisted every five seconds, even during detail capture. Leader scans run every fifteen seconds outside detail. Active detail scans run every second; on each baseline tick, a second row at the same timestamp persists all processes with canonical host and service values. Intervening baseline rows carry cached leaders with per-row UTC and monotonic observation times. One-minute host rollups count baseline rows only and are rebuilt every three baseline samples, at bucket rollover, and on clean stop; restart backfills the latest raw baseline bucket after an interrupted stop. A failed detail write leaves its already committed baseline row intact. Detail data is evicted before baseline under pressure; recent baseline is protected. A process is identified by boot ID, PID, and start ticks. Each process row includes `ppid` from the same proc stat snapshot; consumers should resolve that parent PID only among rows in the same snapshot because the parent may exit or its PID may be reused.

`rusqlite` provides the sole SQLite writer and uses its bundled SQLite build for predictable WAL support; `flate2` compresses process blobs. `tempfile` is used only by isolated SQLite tests. Other runtime dependencies match the prototype providers. The collector never performs privileged or state-changing service actions.
